## DocumentDataの扱いの調整

同様にタブでドキュメントを開くアプリにおいては以下のような構造になっている。

```TypeScript
export interface DocumentState {
    path: string;
    content: string;
    metadata: Record<string, any>;
    documentType: NovelaidDocumentType;
    isDirty: boolean;
    // 各ペイン・各スロット（メイン/プレビュー）の表示状態。'none'ならタブが表示されない。
    leftMainView: DocumentViewType;
    rightMainView: DocumentViewType;
    leftPreviewView: DocumentViewType;
    rightPreviewView: DocumentViewType;
}

export interface TabItem {
    path: string;
    isPreview: boolean;
}

interface DocumentContextType {
    openDocuments: DocumentState[];
    activeLeftItem: TabItem | null;
    activeRightItem: TabItem | null;
```

現在の実装との違いとリファクタリングの方向性を検討。
まず、名称をDocumentDataからDocumentStateに変更。
これは現在も純粋なデータではなく状態保持としているため。

管理方法としての大きな違いは、DocumentStateに開いているタブ情報を持たせている点です。  
これにより、ドキュメントのライフサイクルの管理が確実で容易になります。  
なお、その弊害としてはタブの並び順管理等は行えなくなります。
